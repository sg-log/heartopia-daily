# 受信用チャンネルへ公式URLを貼ってギフトコードを復旧

## 通常操作

有効化後、自分のDiscordの受信用チャンネルに公式XのURLを貼る。
通常は次の5分確認でコード・報酬・交換期限を取得し、既存の自動登録APIに渡す。
公式投稿のURLを貼る行為をその投稿のギフトコードの登録指示として扱う。別途チャット承認は求めない。
登録済み・非表示コードを重複追加・非表示解除しない。新規登録時の既存ギフトコードのお知らせ処理は従来のものを利用する。

## 対象

- DISCORD_GIFT_CHANNEL_IDで指定した受信用チャンネルのみ。
- 既定では、そのサーバーの所有者本人の直接投稿のみ。
- 所有者以外を本人として使う場合は、GitHub Repository Variable DISCORD_GIFT_URL_USER_IDSに本人のDiscordユーザーIDを設定する（カンマ区切り）。
- Bot投稿、Webhookによる転送、他人の投稿、転送メッセージのスナップショットは手動依頼として扱わない。
- Heartopia_JP / myheartopia の https公式投稿URLのみ。x.com / twitter.com のURLを正規化し、追跡パラメータを除去する。
- 本文に直接貼ったURLが対象。埋め込みカード・返信先・短縮URLからは依頼を推測しない。
- 1メッセージは最大3つの公式投稿まで。最新100メッセージから未処理の依頼を古い順に1メッセージずつ処理する。

## 内容確認と再試行

検索インデックスを経由せず、指定された公式投稿そのものを取得する。
既存の公式X取得器で投稿者と全文を確認し、既存パーサーでコード・報酬・期限を解析する。
本文が省略されている、期限が不明、コードが複数などの場合は推測して登録しない。
通常のingestOfficialXGiftBatchに渡し、競合・要確認・無視の結果を完了とは扱わない。
保存後は公開getGiftCodesを再取得し、コード・報酬・期限の一致を確認する。
失敗した場合は最大3回（通常の5分確認間隔）試し、それ以降は確認が必要な依頼として次へ進む。
保存後の再取得だけが失敗した場合も、次回は既存の重複抑止により二重追加・二重ギフト通知を防ぐ。
元の公式転送用カーソルは変更せず、手動依頼専用の状態をGAS Script Propertiesに保持する。

## 復旧結果の通知先

復旧の成功・失敗・確認依頼は、利用者が指定した本人のサーバーの「自動更新用」へ送る方針。
既存の天気確認用WEATHER_DC_WEBHOOK_URLを使用するが、送信前にWebhook情報を読み取り、受信用チャンネルと同じサーバーに属することを必ず確認する。
別サーバー・不明な送り先の場合は送信せず、実行ログへ通知失敗を記録する。フレンドサーバーのギフトコード通知用Webhookへ代替しない。

GitHub Repository Variable DISCORD_GIFT_URL_FEEDBACK:

- personal（workflow未設定時の既定値）: 上記の本人用Webhookへ復旧結果を送信する。
- none: 復旧の結果メッセージは送信しない。

BotにSend Messages権限を追加する必要はない。
通知が失敗しても他のサーバー・チャンネルへ転送しない。公開データとの一致が確認できた登録を、通知失敗だけで再登録しない。
通常の新規ギフトコードのお知らせと、ここで追加する復旧結果の通知は別の処理である。
復旧結果の通知はメンション・リンクプレビューを抑止する。
mode=testは通知先のサーバー所属とチャンネルIDも読み取り確認できるが、メッセージを送信しない。WebhookのURL・トークンは実行結果へ出さない。

## 有効化と確認

GitHub変更とGASのgiftUrlRecoveryStateアクションの反映が必要。
GASが未反映の間は状態取得で停止し、コード登録を行わない。
最初の自動便は有効化時点の最終メッセージIDを記録するだけ。過去に貼ったURLは勝手に再処理しない。
その後に貼ったURLを登録指示として受け付ける。利用者が有効化前に貼っていたURLは、有効化後に貼り直す。
mode=testはDiscordの読み取りのみで、状態保存・コード登録・結果返信をしない。
通常のDiscord転送取込・公式X補助取得とは別ステップで実行し、この機能の失敗でそれらを停止しない。
GASは稼働中の全ファイルを取得・保持して反映する。部分フォルダのclasp pushは禁止。
